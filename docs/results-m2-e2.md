## 三、判据判定（§4 E2 预注册）

**判据**：惊喜写入在记忆容量效率上显著优于全量写入（不退化保持率）。

| 分量 | 判定 | 证据 |
|---|---|---|
| ① 记忆价值（臂1/2 > 臂0） | ✅ **通过** | arm1 keep_A 0.160 / arm2 0.050 >> arm0 0.000（4000 步）。回放显著抵抗灾难性遗忘：从 0% 到 5-16% |
| ② 容量效率（臂2 ≥ 臂1） | ❌ **未通过** | arm2（169 条）0.050 < arm1（2000 条）0.160——惊喜子集不足以支撑保持，**"容量效率"方向相反** |
| ③ 域 B 进度不退化 | ✅ **通过** | arm1 0.444 / arm2 0.434 ≥ arm0 0.378——回放臂域 B 学习反而更好（回放正则化正效应） |

**结论：E2 主判据未通过**（②失败）；存储层"回放可抗遗忘"获得支持（①③通过），但"惊喜触发写入更高效"的 Titans 式假设**在 7M 底座 + 域迁移场景被证伪**。

## 四、解读与归因

1. **全量 > 惊喜（容量效率反转）**：惊喜筛选（top 8.5%）丢弃的中低误差样本对域 A 表示保持有贡献——保持需要**覆盖广度**（全量回放提供完整分布覆盖），而非聚焦高误差。Titans/EM-LLM 的"惊喜=事件边界"假设成立场景是**长上下文推理侧检索**（token 级 NLL 惊奇），E2 测的是**训练侧跨域保持**（权重保护）——两个机制不同，结果不矛盾但不可互相搬运
2. **回放的双重正效应**：① 保持（arm1 0.160 vs arm0 0.000）② 域 B 正则（prog_B 0.444 vs 0.378）——回放样本提供域 A 分布约束，抑制对域 B 的过拟合
3. **arm2 的 169 条记忆场为何弱**：惊喜阈值（mean + 1σ）筛掉的 91.5% 样本里含大量"低误差但具代表性"的域 A 结构——对保持而言，代表性 > 意外性
4. **结论口径（v0.2 定位）**：E2 = 确认实验。存储层"回放可抗遗忘"确认，但 E2 判据失败 → 按定位"若通过即归档"的反面：**E2 归档但带负结果**——惊喜写入假设修正为"全量回放优先"，回放接口本身（r=0.25 通道）获实证支持，E3-D（方案 D 夜间回放）依赖的接口可用性不受影响

## 六、工程备注（本实验修复链，供复现）

1. **carry batch 维度**：臂 0 无回放时 n_replay=0 → carry 维度必须匹配真实 batch（BS）
2. **ptrm_infer 解包**：返回 (best_pred, latents) 元组，eval_domain 需取 [0]
3. **sparse embedding 动态 batch**：CastedSparseEmbedding 训练分支 local_weights 固定构造时 batch_size → 拆分 forward 需取前 N 行（monkey-patch，未改共享文件）
4. **显存拆分**：160 batch 需 ~9.6GB > 8GB → 域B(128)/回放(32) 分两次 forward 梯度累积，峰值 6.9GB
5. **缓存池碎片**：128/32 交替分配使 reserved 膨胀至 7.3GB（在用仅 125MB）→ 每 100 步 empty_cache（降至 282MB）
6. **CUDA sticky error**：OOM 崩溃后需等 GPU 完全空闲再启新任务（残留上下文导致 illegal memory access）
