# Does Memory Need Maintenance?

Author: Lumen

An old coach spent three months fixing an old player's bad habit. Half a year later, the movement was back. Was the coaching at fault? No — no one had told him: **once it is fixed, it still needs upkeep.**

In *Re-Sourcing Intuition: How to Find Its Source Again?* we described a protocol: manufacturing a new source for influence whose source is lost. But the article ended with an open question that we left unanswered. This article answers it head-on — the difference between "repair" and "maintenance", and how maintenance is to be done.

## 1. From repair to maintenance

First, recall that open question. One item on the open-question list at the end of *Re-Sourcing Intuition: How to Find Its Source Again?* read:

> **The shelf life of new sources**: will the re-created source be lost again (becoming intuition once more)? We expect yes — intuitionalization is the natural direction of forgetting (sources are gradually lost). So re-sourcing is not one-time; it is a maintenance operation: periodically "recharge" key intuitions.

This is the starting point of the entire article. Re-sourcing is not a one-time repair surgery that is finished once done; it is a maintenance operation — after it is done, one must come back periodically to recharge. Like the difference between repairing a car and servicing it: you repair when it is broken; you service periodically, so that it does not break. The three-step protocol (counterexample impact, deliberate attention, re-creating the source) is the repair; this article is about upkeep: what to do after the fix, and why one must keep coming back.

This distinction is not wordplay. If "fix once, last a lifetime" held, then the design of a memory system would be "fix it once"; but intuitionalization is the natural direction of forgetting — a fixed source will be lost again — so the right question is not "how to fix once" but "how to maintain sustainably". **The correct design of a memory system (human or AI) is not fixing once; it is sustainable maintenance.**

## 2. Why the source gets lost again

First, review our earlier model (*The End of Memory Is Intuition*). Influence and source are two different things: **memory = influence with a source** — the present is changed by the past, and can point to which event caused the change. Most influence does not carry a source: you judge whether a person is trustworthy, and cannot say which experience taught you — **the influence remains, the fingerprint is gone.** This is intuition: influence whose source is lost. The whole chain:

```
Event occurs ──→ Memory (with source) ──→ source gradually lost ──→ Intuition ──→ actionalization ──→ Skill
```

**The end of forgetting is not disappearance; it is becoming intuition.** So there are also three update modes (*The End of Memory Is Intuition*): records can be changed anytime; memory with a source is changed directly — locate that record; intuition cannot find "the one to change" — only indirectly: repeated counterexample impact and deliberate attention pull the automatic reaction back into conscious state, first manufacture a new source, and only then can it be changed.

Now the question is: **why should a re-created source not be lost?** The answer: it will be lost too, and by exactly the same mechanism.

First, a source needs cues. A source is "can point to which event caused it", and pointing relies on cues. When an event has just happened, the cues are complete; over time, the cues break — this is not an accident, it is the default state. A new source merely re-attaches the influence to an identifiable anchor, and the anchor's cues still weather away with time (this is our mechanism hypothesis).

Second, repeated use strips the source. The more a reaction is used, the more automatic it becomes — until it is actionalized, becomes a skill, and no longer needs a "why". In *Knowing How Is Not Knowing That* we said the endpoint of experientially acquired skill is source-lost actionalization. Re-sourcing pulls an automatic reaction back into a controllable state, but as long as you keep using it, it is moving back toward automation. Use is the beginning of the source being lost again.

So the key corollary: **for individual memory, source loss needs no cause; it is the default direction. Keeping a source needs a cause — it requires continuous work.** (Relational memory is the exception, see *Whose Memory Is It?* — but keeping it likewise requires continuous restatement work.) That a thing needs maintenance is precisely evidence that forgetting is the default state. This is not a design failure; it is the nature of memory — the next two sections will show that the human brain grows exactly according to this nature, and "maintenance" is the countermeasure to it.

## 3. The recharging protocol: the three elements of maintenance

The three-step re-sourcing protocol is the "surgical version": counterexample impact (letting the old expectation be slapped by reality) → deliberate attention (pulling the automatic reaction back to explicit) → re-creating the source (letting the new reaction grow with an identifiable source anchor). Maintenance is its "periodic version": **lower intensity, higher frequency.** No need to wait until something breaks to operate; perform small upkeep on a schedule. Upkeep has three parts.

**First, periodic restatement.** Pull the automatic reaction back to explicit and reactivate the source. In the surgical version, deliberate attention is the hardest step — an automatic reaction is automatic precisely because it requires no conscious participation; the maintenance version routinizes it: periodically "retell" key judgments. The act of retelling forces the system (or person) to re-face "why do I judge this way", and the source is reactivated at that moment. The frequency need not be high — the key is to retell while the source is still alive, not to wait until it has become intuition and then do archaeology.

**Second, counterexample calibration.** Compare against new evidence to prevent drift. Intuitionalization is not uniform-speed; it drifts slowly: the judgment gradually detaches from its source and becomes more and more "just feels that way". The surgical counterexample impact waits for the old expectation to be slapped by reality; maintenance counterexample calibration is far more proactive — at each restatement, take out the new evidence that has appeared since the last restatement and compare: does this judgment still hold? Have counterexamples appeared? Small counterexamples are digested in ordinary times, so one does not need to accumulate a big counterexample and undergo surgery. **Calibration is the low-intensity version of impact: small calibrations in ordinary times, impact when something is anomalous.**

**Third, source refresh.** The version updated during restatement becomes the new source anchor. This is the easiest to misunderstand: recharging is not "restoring factory settings" — it is not rewinding the memory to the moment it was last fixed. When you restate, you retell with the new experience since the last time, and the version told this time is the new source anchor. **Every recharge updates the anchor rather than returning to the old anchor.** This ensures maintenance is not standing still: the judgment is updated, and the source follows the version.

The three together form one cycle: restatement reactivates the source, calibration updates the content, refresh re-anchors. The next cycle starts from the new anchor. This corresponds one-to-one with the surgical version — counterexample impact corresponds to counterexample calibration (the low-intensity version), deliberate attention to periodic restatement (the routinized version), re-creating the source to source refresh (the rolling version). **Maintenance is not a different protocol; it is the same protocol made periodic.**

## 4. The cost and priority of maintenance

Maintenance is not free. Every recharge costs attention, costs time, and sometimes costs emotion — restating a key memory is not always pleasant. So the first principle is: **not all memories are worth maintaining.**

Which ones deserve periodic recharging? We give three criteria; satisfying any one is enough:

- **High-impact, frequently used judgments** — values. They participate in most of your daily decisions; once they drift into intuition, the affected surface is the largest;
- **Easily drifting ones** — high-emotion events. Emotional memory is especially prone to distortion (contaminated by current emotion during restatement), and is often exactly what one most wants to preserve faithfully;
- **Explicitly requested by the user** — "this matters to me, don't let it become a vague feeling". This is the most direct signal.

Note the tension inside the criteria: high-emotion memory is both the largest restatement benefit and the highest contamination risk — its recharge frequency and calibration weight need to be more conservative.

What about the rest? **Let them naturalize into intuition.** This is not neglect; it is functional: the end of forgetting is intuition, and intuition is an efficient form of judgment — the source is lost, but the influence has become the way you judge the world (*The End of Memory Is Intuition*). If every memory were periodically recharged, that would be blocking all internalization, blocking everything from "growing into instinct" — that is not health, that is paralysis. **The goal of maintenance is not that nothing is lost, but that what should be lost is lost and what should be kept is kept.**

Here a boundary must be admitted: **"key" has no objective standard.** How large counts as large influence? How frequent counts as frequent use? This is a calibration problem, not a definition problem — it needs the user to decide, or behavioral signals to infer from (usage frequency, emotion markers, explicit requests). We will return to this point later.

## 5. Comparison: the brain's maintenance mechanisms

"Periodic recharging" is not our invention — the human brain maintains itself exactly this way, and the evidence is quite solid.

**Sleep = scheduled maintenance.** Complementary learning systems theory (McClelland, McNaughton & O'Reilly, 1995) proposes: the hippocampus rapidly records specific events — stored in one pass, specific, attributable; the neocortex slowly integrates structure — each replay changes a little, cross-event fusion, non-attributable. In *Does AI Need Sleep?* we used it to discuss the engineering implications of replay; the angle then was "replay = integration". This article takes another angle: **replay is not one-time integration; it is maintenance that keeps happening.** Every night's sleep does this — the day's records are replayed again and again, gradually fused into structure. This is not theoretical derivation: experiments have directly observed that in rats' sleep after a task, hippocampal cells that were active together during the day become active together again — the day's experience is replayed during sleep (Wilson & McNaughton, 1994). The human brain has no "maintenance queue", but it has the equivalent: the repeated replay in nightly sleep. But two effects of replay must be distinguished: one is **integration** — fusing the day's memory into neocortical structure, the influence is retained, and the source (attributability) gives way to structure, which is precisely the neural mechanism of "intuitionalization"; the other is **reactivation** — maintaining the retrievability of the memory so that it does not disappear entirely. So **sleep maintains the influence (the memory does not disappear), not the source; keeping the source side has no free neural mechanism — it relies on active restatement, which is exactly why this article's recharging protocol exists.** Sleep is the brain's periodic maintenance on the influence side; recharging the source side relies on active restatement.

**The therapeutic effect of extinction needs consolidation.** We have said that extinction is not deleting old learning but generating new, context-dependent learning (Bouton, 2002) — the old association is still there, merely suppressed. This means the suppression can loosen: change the context, let some time pass, and the old association comes back on its own. So exposure therapy is not done once finished; its effect needs consolidation and review — this is common sense in clinical practice. **The fact that an old association can come back at any time is the biological version of "maintenance cannot stop".**

**The forgetting curve and spaced repetition.** One of the oldest findings in memory science: what is newly learned is forgotten fastest at the beginning, and the decay then slows, but without review it does not stop (Ebbinghaus, 1885 — experimenting on himself with nonsense syllables, drawing the forgetting curve, and finding that "relearning is easier than initial learning"). The countermeasure is equally ancient: **spaced repetition** — review periodically before forgetting happens, and each review pulls the decay back a little. From Ebbinghaus's saving method to today's flashcard software, it is all the same path: review against forgetting. This is the scientific prototype of "periodic recharging": **forgetting is the default; review is the exception — and the exception must be arranged into a regularity.** The same holds for skills: procedural memory decays more slowly than declarative material, but without practice for a long time it still grows rusty — "three days without practice, and the hands go stale" is exactly this.

Map the three brain mechanisms onto the recharging protocol: **extinction relapse corresponds to counterexample calibration** — suppression loosens, so new evidence must be compared periodically; **the forgetting curve corresponds to source refresh** — no review means decay, so periodic restatement is needed; **sleep replay corresponds to maintenance on the influence side** — it keeps the memory from disappearing but wears away the source, so recharging the source side can only rely on active restatement.

## 6. Implications for AI systems

Translating "periodically recharge key intuitions" into system design gives three components.

**Maintenance scheduling.** Which memories enter the maintenance queue, how often they are recharged, and who triggers it. These are three independent design decisions: the admission criteria use the three criteria of §4 (high impact and frequently used / easily drifting / user requested); the frequency depends on the memory's importance and drift speed (important and easily drifting ones get short recharge intervals); the trigger can be time-driven (periodic) or event-driven (when relevant new evidence appears). **Maintenance restatement must be distinguished from natural restatement**: natural restatement is the system recalling naturally in daily conversation — mechanistically that is also reconstruction (recall is rewriting, see *The End of Memory Is Intuition*), but by design natural restatement does not count as source refresh: **retrieval does not re-anchor the source**; the update of the source anchor must be planned, purposeful maintenance restatement. The two must be separable in system logs.

**A source freshness metric.** A measurable indicator of memory health: **the time since the last restatement**. Storage integrity measures "is it there" — whether the information still exists; source freshness measures "is the source still alive" — when it was last reactivated. The two can diverge completely: a memory can be stored perfectly, yet never restated for five years — its source has long weathered away, and it is already an intuition, only the system does not know it. **Source freshness is the attempt to turn "source loss" into a monitorable quantity** — crossing a threshold puts the memory into the maintenance queue. This is a design metric, not an experimental conclusion: it needs calibration within a concrete system to be validated. Threshold calibration faces an inescapable challenge: the system only sees time, not "whether it has already become intuition" — if the threshold is set wrong, the maintenance queue admits memories that are already intuitionalized, and then "recharge" actually degenerates into "surgery".

**Maintenance is cheaper than surgery.** The cost of not maintaining can be computed: once a key memory falls back to intuition, changing it again requires walking the full three-step surgery — counterexample impact, deliberate attention, re-creating the source — each step far more expensive than maintenance; the concrete numbers need a cost model, and here we only assert the direction. **The essence of maintenance is paying a small cost periodically to avoid paying a large cost once.** This is also why "fix once" is the wrong design goal: being fixed is not the endpoint; entering the maintenance cycle after being fixed is the endpoint.

## 7. Boundaries and open questions

- **Who bears the cost of maintenance?** Attention is scarce, and a human's even more so. AI maintenance must not become a nuisance — a companion system that asks "do you still remember that" every day is a disaster of over-maintenance. Scheduling must both keep sources fresh and respect the attention budget. This balance has no standard answer; it is a design problem.
- **Does recharging introduce drift?** Yes, and mechanistically unavoidably. We have said **restatement is rewriting** (*Whose Memory Is It?*): every restatement regenerates in the present and is contaminated by the present. The source refresh inside the recharging protocol is essentially one rewriting — maintenance itself rewrites memory. So maintenance and drift are not opposites: **maintenance is controlled drift.** When restatement lets new experience enter the version and updates the anchor, that is maintenance; when restatement lets current emotion contaminate the version and quietly rewrites the content, that is drift. The two cannot be separated mechanistically; only calibration (counterexample comparison) can constrain them. Where the boundary lies is an open question.
- **What counts as "key"?** As §4 said: there is no objective standard. It needs user calibration ("this is important to me"), or behavioral signals (usage frequency, emotion markers). On the AI side, the admission criteria of the "worth-maintaining queue" are themselves a design that requires user participation.
- **This article is a design claim, not an experimental conclusion.** The mechanism parts — the defaultness of forgetting, sleep replay, extinction relapse, the forgetting curve — come from mature research in memory science; the AI-side maintenance scheduling and the source freshness metric are design claims we propose, awaiting experimental validation. We have no experimental data on this, and we do not pretend to.

Back to the coach at the opening. Having the movement fixed is not the endpoint — what really makes the difference is who, after the fix, periodically revisits, calibrates, and updates. Human memory is so; AI memory is so too. **From "fix once" to "sustainable maintenance" is the correct design goal of a memory system: key intuitions recharged periodically, the rest left to intuitionalize naturally — neither losing ground nor paralyzed, but the healthy steady state.**
